# 07｜第一版实现说明（v0.4）

> 版本：v0.4 · 2026-11-11。本文描述代码里实际实现的内容，决策依据见 [decisions.md](decisions.md)，模型能力与价格见 [06](06-模型能力与约束.md)。02–05 中与本文冲突的 v0.2 内容以本文为准。
>
> v0.4 的变化：多供应商并存。视频模型有 Seedance 2.5（火山方舟 / BytePlus）与 Gemini Omni 1.2 Flash（Google Gemini API），图片模型有 Seedream 5.0 pro 与 Nano Banana 2.1；模型组合由服务端配置，记录在项目上（D-45、D-46）。

## 1. 原理（和 Kickart 的对应关系）

先用文字把视频方案定好（便宜、可以反复改），再把每个镜头分别交给视频模型生成一小段，最后拼成一条，字幕在合成时叠加。

| 步骤 | 做什么 | 对应 Kickart |
|---|---|---|
| 商品素材 | 上传商品图（可选人物图、场景图），填写名称、描述、卖点、目标人群；每张图自动检查人脸与质量 | 素材抓取 / 上传 |
| 素材理解 | DeepSeek 看图，提炼具体可拍的卖点（AI 建议需商家确认）、诊断图片、提示缺什么 | 素材理解 |
| 故事线 | 一次 4 条，类型各不相同，含标题、风格、时长（15/30/60 秒）、开场钩子、按时间段的内容；可换一换、可按方向重新生成 | Storyline |
| 故事板 | 逐镜脚本（7 个字段 + 口播 + 字幕 + 时长 + 引用的参考图）；人物图、场景图由项目的图片模型（Seedream 或 Nano Banana）文生图自动生成，商品图可以 AI 换背景（原图保留） | Storyboard：逐镜脚本 + 参考图 |
| 生成确认 | 商家确认清晰度和要生成的镜头 | （Kickart 按创点扣费） |
| 逐镜头生成 | 每个镜头调用一次项目的视频模型（Seedance 2.5 或 Gemini Omni 1.2 Flash），并发按供应商账号分别限制；结果立即转存并规范化 | 片段化生成 |
| 合成 | Remotion 拼接片段并叠加字幕，FFmpeg 写入 AI 标识、截封面；质检只记录 | 合成视频 |
| 修改 | 改字幕只重新合成；重做某个镜头只生成这一个；可回退到旧版本 | 局部重新生成、精修（简化） |

每个页面都有“对话修改”：大模型（默认 DeepSeek）把一句话转成预先定义的修改操作，商家看过对比点“应用”才生效。

H5 底部导航有五格：主页、广场（这一版是占位页）、发布、作品、我的。点“发布”直接进入发布表单，不先填商品名称；选好第一批商品图时才创建项目，随后自动做素材理解，商家没填名称时由 AI 按图片起名（D-53 至 D-55）。

商家不选模型。新建项目时，服务端按 `.env` 的 `VIDEO_MODEL` / `IMAGE_MODEL` 把模型组合记录到项目上，这个项目之后的故事板、生成、重做都用这一组；改配置只影响之后新建的项目（D-46）。

## 3. 数据模型

| 表 | 作用 | 要点 |
|---|---|---|
| User / Session | 用户与登录会话 | 令牌只存哈希 |
| Product | 商品信息与最近一次素材理解结果 | — |
| ProductFact | 卖点 | `MERCHANT_CONFIRMED` 才能进入口播和字幕；`AI_SUGGESTED` 需确认 |
| Asset | 图片（商品/人物/场景，上传/AI 生成） | 人脸状态与处理方式、质量诊断、AI 生成方式、供应商原始链接与有效期、AI 修改商品图的比对结论 |
| Project | 创作项目 | `currentOutputId` 指向当前成片版本；`videoModel` / `imageModel` 是新建时记录的模型组合（登记表键名） |
| Storyline | 故事线（按批次） | 换一换生成新批次 |
| Storyboard | 故事板（按版本） | 每次修改生成新版本；保存时按项目视频模型的能力校验镜头时长；`videoModel` 记录所用模型 |
| GenerationJob | 一次确认生成 | 幂等键唯一；FULL（全部镜头）/ RESHOOT（部分镜头） |
| Clip | 一个镜头的一次生成（片段版本） | 版本只增不改；保存供应商、模型键名、请求（不含图片数据）、供应商任务 ID、原始用量、实际时长；`providerVideoUrl` 是结果位置（Seedance 为链接，Gemini 为 interaction 引用），转存后清空 |
| Output | 成片版本 | 每个镜头选中的片段 + 字幕；分享令牌 |
| QcRecord | 质检记录 | 只记录，不拦截 |
| ChatEdit | 对话修改提案 | 提案 → 应用 / 放弃；基于的故事板版本变了则拒绝应用 |

## 4. 状态

**生成任务**：`QUEUED → GENERATING → COMPOSING → QC → COMPLETED`，另有 `PARTIAL_FAILED`（部分镜头失败，成功的保留，可以只重试失败的镜头）、`FAILED`、`CANCELLED`。

**片段**：`QUEUED → SUBMITTING → SUBMITTED（供应商排队）→ RUNNING → TRANSFERRING → SUCCEEDED`，或 `FAILED` / `CANCELLED`。

规则：

- 只有任务还在排队（`QUEUED`）时可以取消；本地排队的片段直接取消，已提交但供应商还在排队的调用供应商的取消接口；已经开始生成的不能取消。
- 并发数与每分钟请求数按供应商账号分别计算（火山默认 3 / 180，Gemini 默认 3 / 30，均为配置项）；一家满了不影响另一家的片段提交。
- 提交时遇到 429、5xx、网络错误自动退避重试（最多 5 次）；参数错误等直接失败并给出原因。Gemini 提交超时不重试（无法确认是否已创建任务）。
- 从提交起超过 30 分钟（配置项）标为超时失败。
- 提交中途进程退出、无法确认是否已提交的片段，5 分钟后标为失败（不自动重提，避免重复费用）。
- 结果在供应商侧有保留期限（Seedance 链接 24 小时）：成功后立即下载转存，转存失败最多重试 5 次。Gemini 转存成功后删除 Google 侧的 interaction 记录（里面有商家的图片和视频）。
- 不自动换模型：项目的模型不可用（如没有配置密钥）时，镜头直接失败并说明原因（D-48）。
- 同一项目同时只能有一个进行中的任务。

## 5. 模型调用

### 5.1 能力登记表（`providers/registry.ts`）

每个视频模型登记：时长范围或固定时长、分辨率、比例、参考图上限、首尾帧、声音、编辑/延长、能否关水印、人脸处理方式、是否支持虚拟人像、地区、并发与每分钟请求数（按供应商账号）、参考图格式与尺寸要求、结果保留时间。故事板的镜头时长、上传图片的校验、请求参数、可选分辨率都按项目所用模型的登记项约束。

| 键名 | 供应商 | 单镜头时长 | 分辨率 | 参考图 | 人脸 | 虚拟人像 |
|---|---|---|---|---|---|---|
| `seedance-2.5` | volcengine-ark | 4–30 秒 | 480p / 720p / 1080p | 30 张 | 只接受虚拟人像或同账号 Seedream 产物 | 有 |
| `gemini-omni-1.2-flash` | google-gemini | 3–15 秒 | 720p / 1080p | 6 张（最多 2 个人物） | 上传的真人脸图不发送 | 无 |

| 图片模型 | 供应商 | 9:16 尺寸 | 输入图 |
|---|---|---|---|
| `seedream-5.0-pro` | volcengine-ark | 1152×2048 | 10 张 |
| `nano-banana-2.1` | google-gemini | 768×1376（1K） | 14 张 |

新增模型：在登记表加一项，实现 `VideoProvider`（`compile`、`createTask`、`getTask`、`cancelTask`、`downloadResult`，可选 `cleanup`），在 `providers/factory.ts` 里按 `provider` 登记适配器，再把 `.env` 的 `VIDEO_MODEL` 改成新键名。图片模型同理（`ImageProvider`）。业务代码通过 `ModelHub` 按项目记录的键名取适配器，不直接引用某一家供应商。

### 5.2 时长分配

`packages/shared/src/duration.ts`：总时长按权重分给各镜头，每个镜头取模型允许的整数秒，总和严格等于总时长（动态规划，结果确定）。支持连续范围（Seedance 4–30 秒）和离散取值（如只支持 4/6/8 秒的模型）。镜头太多或太少时给出可读的原因。

### 5.3 Seedance 提示词（`providers/video/seedance.ts`）

按 Kickart 视频提示词公式逐行编译：参考图主体 → 视频类型 → 运镜方式 → 主体动作 → 场景环境 → 口播/音频 → 一致性约束，结尾“不生成字幕和水印”。

- 参考图按“商品 → 人物 → 场景”编号为 `@图像N`；AI 修改过的商品图之后紧跟商品原图，说明“用于还原外观细节”。
- 口播放在 `{}` 里（Seedance 台词语法），并要求“严格按台词生成口播，不增减台词”；所有镜头用同一段音色描述。
- 不写任何背景音乐要求（D-13）。
- 商家文字中的 `{}【】()<>@「」[]` 先清洗，避免改变提示词语义。
- 请求：`ratio=9:16`、`resolution`、`duration`=镜头时长、`generate_audio=true`、`watermark=false`；有参考图时 `omni_reference_task_type=reference`（V-01 待核对）。
- 海外改走 BytePlus ModelArk：接口相同，只改 `ARK_BASE_URL` 和模型 ID（V-13 待核对）。

### 5.3a Gemini Omni 提示词与请求（`providers/video/gemini-omni.ts`）

官方只对英文做了完整评估，所以模板用英文；故事板里的中文内容原样放入（D-49：这一轮不改语言）。逐行编译：

- 第一行要求单个连续镜头、不切镜（Omni 默认会自己切成几个镜头）。
- 参考图按“商品 → 商品原图 → 人物 → 场景”编号为 `Image N`，用自然语言说明各自是什么，并写明“只用于保持外观一致，不是视频画面”。不用 `<IMAGE_REF_0>` 这类控制标签（官方已废弃）。
- 超过上限的参考图（6 张、最多 2 个人物）改成文字描述。
- 主体、视频类型、运镜、动作、场景各一行。
- 口播：给出音色描述，要求逐字说一次；含中文时注明 Mandarin Chinese。没有口播时写明无对白、无旁白。
- 一致性约束；最后一行要求不渲染字幕和叠加文字。不写任何背景音乐要求（D-13）。
- 商家文字中的引号、尖括号、各类括号与 `@` 先清洗。

请求走 Interactions API：`POST /interactions`，`input` 先放图片（Base64 内联）再放提示词，`response_format={type:video, aspect_ratio:9:16, resolution, duration:"5s"}`，`background=true`；`GET /interactions/{id}` 轮询；`POST .../cancel` 取消；结果视频在 `steps` 的 `model_output` 里以 Base64 返回，转存时再取一次；转存成功后 `DELETE /interactions/{id}`。密钥放在 `x-goog-api-key` 请求头，带 `Api-Revision`（配置项）。

### 5.3b Nano Banana（`providers/image/nano-banana.ts`）

同一个 Interactions 接口，同步返回。`input` 为提示词加输入图片，`response_format={type:image, aspect_ratio:9:16, image_size:1K}`。结果按返回的 PNG 原样保存。

### 5.4 发给模型的图片（`assets.service.ts → toModelImage`）

- 商家上传的图片：本地开发（`MODEL_IMAGE_TRANSPORT=base64`）转为 JPEG、最长边 2048 后以 Base64 发送；上线改为 `signed_url`。
- AI 生成的图片原样发送（不压缩），结果链接未过期时直接用供应商原始链接，以便 Seedance 信任其中的人脸（V-02 待核对）。
- 虚拟人像：`asset://素材ID`，只能发给火山。
- Gemini 一律内联 Base64：遇到链接时由服务端下载后转 JPEG 再发送。

### 5.5 人脸

上传后自动检查。含真人脸的图片在生成前必须处理：

| 选择 | 适用 | 效果 |
|---|---|---|
| 换成虚拟人像 | 人物图，且项目视频模型是 Seedance | 用火山预置虚拟人像的素材 ID；清单在 `config/virtual-portraits.json`，没有配置或项目用 Gemini 时不显示，接口也会拒绝 |
| AI 生成相似人物 | 人物图 | 大模型只描述可泛化的风格（年龄段、发型、穿着、气质），项目的图片模型文生图生成新人物 |
| 不用这张图 | 全部 | 只靠文字描述 |

Seedance 只信任同账号 Seedream 文生图产物中的人脸，且只在 30 天内：生成前检查 AI 人物图是不是 Seedream 生成的、有没有超过 30 天，不满足时提示重新生成。Gemini 项目没有这条限制。

### 5.6 大模型调用

所有调用都要求 JSON 输出并经 zod 校验；业务校验失败（如引用不存在的卖点、镜头数不对、口播超长）时把错误说明发回模型重试，最多 2 次。故事线、故事板开启思考模式，其余关闭。提示词集中在 `creative/prompts.ts`，带版本号 `PROMPT_VERSION`。

供应商可配置（D-47）：`LLM_PROVIDER=deepseek`（官方）、`ark`（方舟托管）或 `openai_compatible`（任意 OpenAI 兼容接口，用 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`，思考参数写法 `LLM_THINKING_PARAM`，JSON 模式 `LLM_JSON_MODE`）。Gemini 的 OpenAI 兼容接口按这种方式配置，还没有实测。

## 6. 合成与标识

- 片段规范化：铺满裁切到目标尺寸、24fps、H.264 + AAC 48kHz、响度 -16 LUFS；没有音轨的补静音。
- Remotion 合成：片段按实际时长依次拼接，字幕按镜头时间段叠加在画面下方安全区（思源黑体 Bold，半透明底、描边）。H5 的字幕编辑页用同一个组件实时预览。
- AI 标识：成片写入 `comment=AI生成内容（AIGC）` 与 `AIGC` 元数据（字段参照 GB 45438-2025，上线前按原文核对）；H5 作品页、作品卡片、分享页显示“AI生成”；视频模型水印关闭。
- 质检：每个镜头抽中间一帧，与商品参考图一起交给 DeepSeek，记录商品一致性与是否出现模型生成的字幕，结果用 `npm run inspect -- <projectId>` 查看。

## 7. 内部接口（`/app/v1`，只给 H5 使用）

| 方法与路径 | 作用 |
|---|---|
| `POST auth/dev-login`，`GET me` | 简易登录 |
| `POST/GET projects`，`GET projects/:id` | 新建、列表、完整状态 |
| `PATCH projects/:id/product`，`POST projects/:id/facts`，`PATCH/DELETE facts/:id`，`POST projects/:id/analyze` | 商品信息、卖点、素材理解（商品名称为空时由 AI 起名，D-54） |
| `POST projects/:id/assets`（multipart），`PATCH/DELETE assets/:id`，`POST assets/:id/face` | 上传、标签、删除、人脸处理 |
| `POST projects/:id/storylines`，`PATCH storylines/:id`，`POST storylines/:id/select` | 故事线生成/换一换、编辑、选定（生成故事板） |
| `PATCH projects/:id/storyboard`，`POST projects/:id/storyboard/duration` | 保存故事板新版本、改总时长 |
| `POST projects/:id/references/:refId/regenerate`，`.../replace` | 参考图 AI 重新生成、换成自己的图或换回原图 |
| `POST projects/:id/readiness` | 生成前检查 |
| `POST projects/:id/chat`，`POST chat-edits/:id/apply`，`.../discard` | 对话修改 |
| `POST projects/:id/generate` | 确认生成（幂等键、故事板版本） |
| `GET jobs/:id`，`POST jobs/:id/cancel` | 任务进度、取消 |
| `POST projects/:id/captions`，`POST projects/:id/shots/:shotId/select-clip` | 改字幕、换回旧片段（都只重新合成） |
| `POST outputs/:id/make-current`，`.../retry-compose`，`GET .../download-url`，`GET .../qc` | 版本切换、重试合成、下载、质检记录 |
| `POST/DELETE outputs/:id/share`，`GET share/:token`（公开） | 分享 |

所有资源都在服务端按用户归属校验，越权访问一律返回 404。

## 9. 已知限制

- 还没有用真实密钥跑过：V-01 至 V-13（decisions.md §5）需要第一次真实调用时核对。其中 Omni 是否支持后台执行（V-06）直接决定 Omni 适配器能不能用。
- Omni 只对英文做了完整评估；现在的画面描述和口播是中文（D-49），效果待实测（V-08）。
- 镜头之间的声音、背景音乐可能跳变：目前只靠统一的音色描述约束。
- 人脸检测由大模型看图给出，只是提示；漏检时视频模型可能拒绝，该镜头失败并提示换成 AI 相似人物（或虚拟人像）。
- 本地开发图片以 Base64 发送：商家图片会压缩到最长边 2048；签名 URL 路径要等接入 OSS 时才能真实验证。
- 没有 Mock 模式：没有填写密钥时，素材理解、故事线等会提示“未配置 API Key”。
- H5 没有推送通知，靠页面轮询刷新进度。
- 模型组合只能改 `.env` 后重启服务；没有管理页面（第一版不做运营后台）。
- 第一版不做：积分、运营后台、爆款模仿、真人授权入库、时间轴精修、Veo 3.1 与其他视频模型的具体接入。
