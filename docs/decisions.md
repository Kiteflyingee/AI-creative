## 2. 已定决策（v0.3 有效）

### 2.1 产品与流程

| 编号 | 决策 | 原因 | 来源 |
|---|---|---|---|
| D-04（v0.3 改） | 生成方式按 Kickart：先准备参考图（商品、人物、场景），每个镜头单独调用一次视频模型生成一段，最后合成成片 | 与 Kickart 原理一致；不绑定某一家模型 | 规划对话 |
| D-24 | 页面流程固定，由代码推进：商品 → 素材理解 → 4 条故事线 → 故事板 → 生成确认 → 作品。商品页、故事线页、故事板页、作品页各有一个“对话修改”框：DeepSeek 把商家的话转成预先定义的修改操作，商家看过修改前后对比、点“应用”才生效；需要调用视频模型的修改一律转到生成确认页 | 可控、可测；保留 Kickart 用对话改稿的方式 | 规划对话 |
| D-37 | 故事线一次 4 条，含标题、类型、风格、时长（15 / 30 / 60 秒）、开场钩子、按时间段写的内容；可“换一换”，也可按一句话方向重新生成 | 与 Kickart 一致 | 规划对话 |
| D-19（v0.3 改） | 成片总时长 15 / 30 / 60 秒；单个镜头时长受系统所选视频模型的能力限制（Seedance 2.5 为 4–30 的整数秒） | 分镜头生成后总时长不再受单次生成上限限制 | 规划对话 |
| D-26 | 参考图分商品、人物、场景三类。人物图和场景图在生成故事板时由 AI 自动生成，商家可以替换为自己上传的图、让 AI 重新生成或用一句话修改；商品图默认用商家原图，也可以让 AI 重新生成（图生图换背景或摆放），原图始终保留，生成视频时原图一并作为参考 | 与 Kickart 一致：先用参考图锁定主体，再让画面动起来 | 规划对话 |
| D-25 | 商家不选择模型，由系统按配置自动选择；商家只选分辨率 | 降低使用难度 | 规划对话 |
| D-07（v0.4 改） | 分辨率 480p / 720p / 1080p 中、项目视频模型支持的档位可选（Seedance 三档都有；Omni 只有 720p / 1080p），默认 720p；画面固定 9:16 | Omni 没有 480p | 规划对话 |
| D-17（v0.3 改） | 字幕不由视频模型生成：提示词要求“不生成字幕”，字幕在合成时用 Remotion 叠加，商家可以修改；改字幕只重新合成，不调用视频模型 | 字幕可改；与 Kickart 后期加字幕一致 | 规划对话 |
| D-13 | 背景音乐：提示词不写任何背景音乐要求，我们不加也不去除 | 交给模型自身能力 | 规划对话 |
| D-38 | 口播由视频模型自带的声音生成；所有镜头使用同一段音色描述；TTS 接口预留，第一版不实现 | Seedance 2.5 自带声音 | 规划对话 |
| D-14（v0.3 改） | 重做镜头进入第一版：只重新生成选中的镜头，其他镜头不动；每个镜头保留全部片段版本，可以对比、可以回退，回退只重新合成 | 原 P-01：验收故事要求“只重做第三镜头” | 规划对话 |
| D-28（v0.4 补充） | 人脸：上传人物图时检测是否有真人脸。有人脸时商家三选一：换成火山预置虚拟人像（`asset://素材ID`，只适用于 Seedance 项目）；让 AI 按照片风格生成相似人物（先用文字描述风格，再文生图，不对真人照片做图生图）；这张图不用作参考。含真人脸的原图不发送给任何视频模型。Gemini 项目只有后两种选择。真人授权入库放到下一版 | Seedance 2.x 不接受直接上传真人人脸，官方提供虚拟人像与信任同账号模型产物两种方式；Omni 不接受含“某些可识别真人”的图片，也没有虚拟人像库 | 规划对话；火山肖像素材方案；Omni 文档 |
| D-29（原 P-02） | AI 标识由我们自行完成：写入视频文件元数据，H5 作品页和分享页显示“AI生成”；视频模型水印关闭（`watermark=false`，即 D-18） | 不改画面 | 规划对话 |
| D-12 | 质检只记录，不拦截成片，也不自动重试 | 质检准确度未验证 | 规划对话 |
| D-05 | 不出样片 | — | 规划对话 |

### 2.2 模型与供应商

| D-40（v0.4 改） | 实现两家：Seedance 2.5（火山方舟 / BytePlus）与 Gemini Omni 1.2 Flash（Google Gemini API）；MiniMax、万相、Veo 3.1 以后按同一接口接入 | 首发海外，需要 Google；保留火山 | 规划对话 2026-11-11 |
| D-27（v0.4 改） | 图片模型同样走统一接口：Seedream 5.0 pro（火山）与 Nano Banana 2.1（Google），由系统按配置选择 | Seedream 与 Seedance 同账号，人物图可被 Seedance 信任；Nano Banana 与 Omni 同一个密钥 | 规划对话 |
| D-03（v0.4 改） | 大模型默认 DeepSeek；可配置为 DeepSeek 官方、火山方舟托管，或任意 OpenAI 兼容接口（见 D-47）；必须使用能看图的模型 | — | 规划对话 |
| D-16（v0.4 改） | 并发数与每分钟请求数按供应商账号分别计算（配置项）：火山个人账号 Seedance 并发 3、RPM 180；Gemini 默认并发 3、RPM 30，按账号实际额度修改；不升级火山企业账号（原 P-03） | 两家账号的额度互不影响 | 规划对话 |
| D-45 | 多供应商并存：视频、图片模型都按能力登记表键名取适配器，业务代码不引用具体供应商；一家的并发满了不影响另一家 | 用户要求支持多个供应商 | 规划对话 2026-11-11 |
| D-46 | 模型组合（`VIDEO_MODEL` + `IMAGE_MODEL`）由服务端配置，默认 Gemini Omni 1.2 Flash + Nano Banana 2.1。新建项目时把组合记录到项目上，之后该项目的故事板、生成、重做、时长校验、可选分辨率、人脸选项都按这一组；改配置只影响之后新建的项目 | 同一条成片不混用两个模型；用户自己在后台配置组合 | 规划对话 2026-11-11 |
| D-47 | 各类模型的供应商都可配置：大模型可用任意 OpenAI 兼容接口（地址、密钥、模型、思考参数写法、JSON 模式）；火山国内与 BytePlus 海外只改接入地址与模型 ID。其他供应商的兼容问题等拿到密钥后再处理 | 用户要求“自由配置，后续做兼容” | 规划对话 2026-11-11 |
| D-48 | 项目的模型不可用时不自动换模型：镜头直接失败并说明原因（例如未配置密钥） | 自动换模型会让同一条成片画面风格不一致 | 规划对话 2026-11-11 |

| D-50 | 这一轮不接 Veo 3.1：Gemini API 上的预览版已于 2026-10-22 下线；正式版只在 Google Cloud，仅 us-central1，没有按量付费，时长只有 4/6/8 秒，参考图模式只能 8 秒且最多 3 张同一主体 | 接入和计费门槛高，能力不如 Omni 适合逐镜头生成 | 规划对话；Google 文档 |

| D-32 | 第一版不计算、不显示费用；供应商返回的用量原样保存 | 先专注视频生成 | 规划对话 |
| D-41 | 调用视频模型前，商家必须在生成确认页确认分辨率和这次要生成的镜头；同一次确认只创建一个任务（幂等键） | 视频调用昂贵 | 规划对话；v0.1 原文 |
