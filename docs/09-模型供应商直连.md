# 模型供应商直连

D-60 取代 New API 网关方案：

```text
H5 → NestJS / ModelHub
       ├─ 文字/看图 → AI SDK 显式 Provider → Vertex / DeepSeek / 方舟 / 兼容接口
       ├─ 图片     → 原生 ImageProvider → Vertex / 方舟
       └─ 异步视频 → 原生 VideoProvider → Vertex / 方舟
```

AI SDK 是服务端依赖，无需 Vercel 部署、账号或 Gateway Key。当前固定 AI SDK 6 和对应 Provider 版本，以适配项目 CommonJS / Jest；不承诺最新 SDK 文档中的全部模型能力已接入。新 API 网关容器已移除，旧 Docker 数据卷保留但不被应用使用。

## 职责

ModelHub 与业务层继续负责能力登记、项目绑定、确认、幂等、镜头版本、供应商账号限流、BullMQ 调度和合成。供应商 SDK/原生适配器只负责协议、认证和模型任务生命周期；不会自动切换模型或账号。

SDK `maxRetries=0`；大模型明确返回 HTTP 429 时，LlmService 最多退避重试 2 次（约 5/10 秒加抖动），JSON 修正过程共享这一预算。尊重 `Retry-After`，要求等待超过 30 秒时直接返回 `LLM_RATE_LIMITED`（HTTP 429）并提示稍后重试。LlmService 这一层不对网络中断、超时及 5xx 自动重发，后台任务的既有队列重试规则另行生效。JSON 输出格式错误仍由 LlmService 追加修正对话，经过 zod 和业务规则校验。付费视频创建发生超时、断网、5xx 或缺少有效任务 ID 时返回 `SUBMIT_UNKNOWN`，停止自动提交，需要核对供应商记录。明确 429 按现有任务退避。已提交任务是否能取消取决于供应商状态；取消失败不伪装为成功。

图片/视频保留原生适配器，是为了保留已验证的多参考图、方舟 `asset://`、异步任务 ID、轮询、取消和 Vertex 转存后清理。SDK 视频的一次调用等待成片，不能直接代替当前可恢复的任务调度。

历史 New API 的任务 ID 不是供应商原生 ID；如有未完成历史任务，先核对旧记录，不自动迁移 ID 或重新付费提交。当前未做真实模型调用，真实账号仍须联调。

## 配置位置

仓库根目录 `.env`（模板 `.env.example`）。更改后重启后端及 worker。默认 Demo 全部用 Vertex，见 [08](08-Vertex-AI接入.md)。其他供应商是可选配置，不需要同时填写。

### 火山视频与图片

```dotenv
VIDEO_MODEL=seedance-2.5
IMAGE_MODEL=seedream-5.0-pro
ARK_API_KEY=你的方舟密钥
ARK_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
SEEDANCE_MODEL_ID=doubao-seedance-2-5-260628
SEEDREAM_MODEL_ID=doubao-seedream-5-0-pro-260628
ARK_VIDEO_MAX_CONCURRENCY=3
ARK_VIDEO_RPM=180
```

海外 BytePlus 使用对应账号地址、密钥和可用模型 ID，不能混用国内账号。人物参考图的同账号信任规则继续有效；视频/图片组合只影响新建项目。

### 大模型

| LLM_PROVIDER | 模型配置 | 认证/地址 |
|---|---|---|
| `vertex`（默认） | `VERTEX_LLM_MODEL` | `VERTEX_PROJECT_ID` / ADC / global |
| `deepseek` | `DEEPSEEK_MODEL` | `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL` |
| `ark` | `ARK_LLM_MODEL` | `ARK_API_KEY` / `ARK_BASE_URL` |
| `openai_compatible` | `LLM_MODEL` | `LLM_API_KEY` / `LLM_BASE_URL` |

四种选项均通过显式 AI SDK Provider 直连，不用网关模型字符串。DeepSeek 官方和方舟当前按 DeepSeek 思考参数传递；其他方舟模型可使用通用兼容配置选择参数写法。

通义、Kimi、智谱等若提供兼容 Chat Completions 接口，可用：

```dotenv
LLM_PROVIDER=openai_compatible
LLM_BASE_URL=供应商对应地域的完整API前缀
LLM_API_KEY=该供应商的密钥
LLM_MODEL=账号可用的多模态模型ID
LLM_THINKING_PARAM=none
LLM_JSON_MODE=json_object
```

`LLM_BASE_URL` 填到 `/v1` 等前缀，不包含 `/chat/completions`。选择 `deepseek` / `reasoning_effort` / `none` 对应具体模型的思考参数；不支持 JSON 模式时设 `LLM_JSON_MODE=none`，业务 zod 校验仍然执行。必须使用能看图的模型；文字模型可用不代表整个创作流程可用。兼容接口仍需按账号做协议与效果验证，未预接全部国内供应商。

## 新模型扩展

1. 文字模型优先使用现有兼容 Provider；协议不兼容时在 `providers/llm` 加显式 SDK Provider，并在工厂与配置登记。
2. 图片/视频在 `registry.ts` 登记新键及真实能力，选择合适的 SDK 或原生适配器，在 `factory.ts` 注册。已有模型键不原地换版本。
3. 验证参考图、人脸、时长、分辨率、用量、取消和结果转存，再修改默认组合；不因 SDK 列出了供应商就认为指定模型已验证。
